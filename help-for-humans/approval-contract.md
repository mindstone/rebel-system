# The Approval Contract

When Rebel asks before an action, you are in charge: approve it or deny it. A denial destroys the waiting action rather than parking it for later. If it still matters after that, Rebel must start again with a new action.

You can allow this action once or, when Rebel can safely enforce the reach, ask it to remember the decision: always, for this conversation, or for this automation. Deny uses the same once-or-remember model. Rebel only offers a remembered choice where it can actually honour it; a missing option is caution, not coyness.

When an approved action is already waiting, what you approved is what runs: the same action with the same details, not an invitation for Rebel to improvise a sequel. There is no “approved, please retry” hand-off on that path.

A remembered permission is not a ceremonial rubber stamp. Rebel can still ask again when its protections find something unusual — say, an email's recipients or content look unlike the routine you meant to allow. That extra question is the deliberate mistake-catcher: mildly inconvenient in exactly the useful way.

If Rebel loses track after an action may have started, it says the outcome is unknown and tells you what to check. It does not quietly turn uncertainty into permission, or claim success because optimism was available.
